# Indeed Poland HTML scraper — requirements

Status: historical scope of the HTML adapter, 2026-11-02. The choice of HTML in the runner was superseded by the [GraphQL import](../indeed-graphql/requirements.md). Task: `oferty-pracy-y81.8`. [PRD](../../PRD.md), [SD](solution-design.md).

The owner's consent to scraping was confirmed in conversation. The limit covers all requests, LinkedIn and Indeed together: at most one/s. First scope: Senior PHP, Poland. The search phrase does not confirm qualification.

- **R-I01:** a separate HTML adapter fetches public lists and details, without GraphQL/the API with the library's key. The existing GraphQL function stays available in the fork for compatibility, but the application runner uses only HTML. A test checks the URLs of all requests.
- **R-I02:** the parser recognises cards, embedded JobPosting JSON-LD, pagination and an explicit empty result. It keeps the stable ID, URL, title, company, description, location and available dates. An unknown format, a consent page or a block is not an empty success. A missing company/description is an unknown; an invalid record is counted and skipped.
- **R-I03:** the salary keeps the amounts, currency, period and evidence. estimatedSalary means an estimate; baseSalary without unambiguous evidence of authorship stays unknown. Missing data does not mean B2B/UoP, net/gross, on-site work or confirmation of seniority. We do not parse arbitrary salary ranges from text.
- **R-I04:** deduplication and detection of pagination without progress end looping. An error on a later page or in details keeps the valid cards, and the result is partial. Explicit limits on time, requests and results, and Retry-After, also apply to details and retries. Absence does not mean expiry.
- **R-I05:** the output keeps the RunResult v1 contract and the structured_job fields. It distinguishes exhausted, result_limit, no_progress, page_error (including the parser), blocked, rate_limited, request_limit, deadline and transport_error; warnings distinguish parser_error, consent_required, detail_error and salary_parse_error. An error without offers is failed; with offers, partial. A completed query does not mean market completeness.
- **R-I06:** all calls go through the existing HTTP controller and the shared runner lock; we do not automatically follow redirects or foreign URLs. We do not handle logging in, CAPTCHA, proxies or circumventing blocks. We support Poland; other scopes end with unsupported_scope.
- **R-I07:** before activation we run a limited pilot. HTTP 403 blocks activation, not offline implementation. The release has a new number and hash; the application identifies the HTML adapter in the fingerprint. Tests cover list/details, dates and salaries, invalid records, empty/changed pages, duplicates, pagination, limits, and 403/429 and consent pages.

Observation of 2026-11-02: one curl request to the public Senior PHP list in Poland returned HTTP 403, title "Blocked - Indeed.com". This is not evidence that the parser works on current valid HTML. Synthetic tests will not replace a later successful pilot. The import stays disabled by default.
