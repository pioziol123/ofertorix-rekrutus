# JobSpy integration with the application — requirements

Status: selected for implementation 2026-11-02. Basis: the [PRD](../../PRD.md) and the owner's decision "scraper indeed zostaw na koniec; realizuj pozostałe elementy" ("leave the Indeed scraper for last; implement the remaining elements"). It covers integrating the existing fork with the worker and the database, without the HTML scraper and without enabling live fetching.

- **R-I01 — run control:** the Indeed source is disabled by default and has no automatic schedule. An attempt at a manual request while the source is disabled does not create a job and does not start Python. Explicit activation and permitted access are the precondition for future live use.
- **R-I02 — independent source:** a separate Indeed run and queue do not change the scope or state of SOLID.Jobs. Concurrent requests and redelivery of the same job do not cause concurrent Indeed fetching. An interrupted worker allows the orphaned run to be marked and a new one to be requested.
- **R-I03 — confined process:** Python receives only explicit search parameters. It does not inherit the OpenAI key, CV data, database credentials or other application secrets. A hung process and its children are terminated after the limit; output that is too large, malformed or non-conforming is rejected. The content of stderr/exceptions does not reach the public error or the database.
- **R-I04 — conforming contract:** the application checks the envelope version, the source, the fork base/version and that the parameters match the run's scope. Bad records and repeated identifiers are reported; valid data stays available. Objects and unknowns keep their meaning; there is no automatic merging with other portals.
- **R-I05 — storage and history:** an offer is identified by the source and its identifier. Saving unchanged data again does not create a revision; a change and a return to earlier content keep successive revisions. Absence from Indeed results never means unavailability or expiry. The original normalised record and the salary origin are preserved.
- **R-I06 — offer view:** saved Indeed offers are readable in the existing list and in the details. The source and the gaps in the PHP/senior qualification are explicit; the search phrase alone does not confirm the requirements. An estimate or undetermined salary origin has a label and is not a positive confirmation of the financial minimum. A missing contract type/work mode remains an unknown.
- **R-I07 — diagnostics:** the state of the source and the run can be read (including limiting, partiality, skipped records, number of attempts). "Query completed" is not presented as a complete sync of the portal. Errors from other sources do not change the status of the last complete SOLID.Jobs fetch.
- **R-I08 — distribution:** the worker installs a specific verified fork package and pinned dependencies. Web does not need Python. Recreating the environment does not depend on the unpublished copy `.local/JobSpy`.

Acceptance: synthetic processes (success, timeout, excess output, error and no secrets), envelopes with errors and duplicates, PostgreSQL/pg-boss tests in isolated schemas (enqueue, saving, revisions, locks, recovery and no expiring), SOLID.Jobs and salary regressions, and the worker container build. The live trial and the assessment of market value remain in `oferty-pracy-y81.5`; they are not a condition for completing the offline integration.
