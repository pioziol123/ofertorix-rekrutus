# Domain documentation

This is a single-context project.

Before exploration, specification or design:
- Read root `GLOSSARY.md` and use its domain terminology.
- Read `docs/product/ustalenia.md` for confirmed product requirements.
- Read relevant decisions in `docs/adr/`, when present.

Missing glossary or ADR files do not block work.
Create them lazily when concepts or decisions are resolved.

Keep the glossary limited to domain definitions.
Record ADRs for decisions involving meaningful trade-offs that are
costly to reverse and would be surprising without context.

Surface conflicts with requirements or ADRs explicitly.
