# Just Join IT — access to ads

Date checked: **2026-11-03**. Scope: the operator's official pages, single ads and help documentation; without running a scraper, bypassing protections or contacting the operator. In addition, the public code of an independent integration was analysed, and single reads of the list, a detail and robots.txt were made in the browser. Search results and ad availability may change.

## Conclusion

Just Join IT contains ads useful for the project, and the public code of other integrations reveals an unofficial endpoint for reading offers; however, **no official public API contract for reading the whole catalogue and no official RSS of offers were found**. This is not proof that they do not exist. Before implementing import and content storage, access and terms of use must be agreed with the operator. The earlier [sources research](../zrodla-ofert.md) points to restrictions on automated extraction in the user terms of 14.07.2026, sections 11.2–11.3; in the current verification the [document](https://s3.eu-west-1.amazonaws.com/public.justjoin.com/regulations/jjit-users-terms-of-service/jjit__regulamin_uzytkownika_justjoinit_14072026) did not open in the web tool, so it was not confirmed whether it still applies or what its exact wording is. The earlier finding is a signal to obtain explicit written consent, not a current legal interpretation.

## Capabilities for the user

The [search](https://justjoin.it/) offers search by job title, company, keyword, and location and radius; the previous review also found filters for technology, seniority, contract, working time, languages, remote work and salary range. These functions concern the user interface; their availability in a possible API and their exact semantics were not confirmed. PHP and Senior are only an example; the technology scope and filter values remain configurable.

[An example Senior PHP Developer ad](https://justjoin.it/job-offer/ideamotive-senior-php-developer-k-m-e-commerce-saas-warszawa-php) shows the PHP category, Senior, Warsaw, remote, full-time, B2B, a salary range with currency, period and amount basis, a description, technologies with a level and the end date of display. The ad also describes requirements and nice-to-have skills, and work for clients of the publishing company without identifying them. The currency value on the page may depend on the view settings. It does not follow that all ads have these fields, that remote means work from Poland is allowed, or that this data is available in an official machine interface. This is one sample, not a measure of coverage.

## Technical analysis of an independent client

The data below comes from [the career-ops client code](https://github.com/career-ops-hq/career-ops/blob/main/providers/justjoin.mjs) viewed on 2026-11-03, not from the operator's documentation. The link points to the moving `main` branch: the commit identifier could not be established, so it is not a lasting record of the version. This is evidence of a client implementation, not a guarantee of operation, completeness or terms of use. The interface has no explicit version in the path; no change or compatibility policy was established.

| Element | What the code read does and what remains unknown |
| --- | --- |
| List | Calls HTTPS `GET https://justjoin.it/api/candidate-api/offers` through a shared `fetchJson`; does not pass a token explicitly in this call. Not all headers of the shared client nor the server's authentication conditions were examined. No official integration contract was found. |
| Parameters | Builds `from`, `itemsCount` (default 100), `cityRadius` (30), `currency` (`pln`), `orderBy=descending`, `sortBy=publishedAt`, `keywordType=any`, `isPromoted=true`. These are the client's values and defaults, not documented limits or a complete list of supported filters. The meaning of `isPromoted` and its effect on completeness are unconfirmed. |
| Pagination | Starts with `from=0`, takes the next value from `meta.next.cursor`, converts it to a number; stops when there is no cursor, on empty parsed results, an invalid cursor, or after 50 pages by default. The 50 limit and the size of 100 belong to the client. Hitting the limit or an error does not prove a complete sync. Offer changes while paging may affect completeness; cursor and snapshot stability were not confirmed. |
| Response and fields | The parser expects an object with a `data` array; it uses `slug`, `title`, `companyName`, `workplaceType`, `locations[].city`, `city`, `lastPublishedAt` and `publishedAt`. It rejects a record without `slug` or a title. This excerpt does not document the full schema, salaries, technologies or the description; a field missing from the parser does not prove it is missing from the response. |
| Identity and detail | The client builds the link `https://justjoin.it/job-offer/{slug}` and does not fetch the detail in this module. Neither the durability of the slug after an edit or republication nor the existence of a durable ID was proven. [Another project](https://github.com/KalMarek7/django-fastapi-ollama) gives an example detail path `/api/candidate-api/offers/{slug}`; this is another client's example, a current response sample is below; permissions and stability were not confirmed. |
| Dates | The client's author interprets `publishedAt` as changing on refresh and prefers `lastPublishedAt` as the earlier date. This is the code author's interpretation, not confirmed operator semantics. Do not equate either of them with the date of first detection, a content modification or expiry. |
| Filters | The client turns the page address `/job-offers/...` into the endpoint and removes its query string; it does not automatically map page filters to API filters. API parameters for technology, seniority, contract, mode and salary and their AND/OR/exclusion semantics were not established. The project's interface should accept any configuration, and assess criteria the source does not support locally, only when there is enough data. |

**Controlled read 2026-11-03:** in the browser, [the list from `from=0` with `itemsCount=1`](https://justjoin.it/api/candidate-api/offers?from=0&itemsCount=1), [the next page](https://justjoin.it/api/candidate-api/offers?from=1&itemsCount=1) and [the detail of one offer](https://justjoin.it/api/candidate-api/offers/iteamly-senior-full-stack-developer-react-java--krakow-java-6483baf2) were opened. All three views returned parsable JSON; the browser did not reveal HTTP codes, so we do not claim that status 200 was checked. A trial from the terminal ended with a DNS error, and the web tool did not open the address; these limitations do not change the browser result. This is a one-off sample, without a test of resilience, the end of pagination, sorting or completeness.

**Additional verification from the worker:** the Python `requests` client, without a proxy and automatic redirects, received **HTTP 200 application/json** for the list `from=0&itemsCount=1`, the second page `from=1&itemsCount=1` and the detail above. For the second page `meta.from=1`, `prev.cursor=0`, `next.cursor=2`, `totalItems=10000`; the detail returned, among others, `id`, `canonicalSlug`, `body`, `employmentTypes`, `requiredSkills`, `niceToHaveSkills`, `locations`, `isActive` and `expiredAt`. At least two seconds were kept between consecutive requests. A single sample does not confirm the completeness and stability of the API or future availability.

The list contained `data` (an array, one record) and `meta` (an object): `from: 0`, `totalItems: 10000`, `prev: {cursor: null, itemsCount: 1}`, `next: {cursor: 1, itemsCount: 1}`. For `from=1` a different `guid`, `prev.cursor: 0` and `next.cursor: 2` were received. The value 10000 may be a limit or a counting result; neither its meaning nor the total number of offers was established. Do not assume that a run over the cursors will cover the catalogue.

In the list sample `guid`, `slug`, `title`, `companyName`, `workplaceType`, `workingTime`, `experienceLevel`, `publishedAt`, `lastPublishedAt`, `expiredAt` were strings; `category` was an object with `key` and `parentKey: null`; `isRemoteInterview`, `isOpenToHireUkrainians`, `isPromoted`, `isSuperOffer` were booleans. `locations` contained objects with the city, street, coordinates and slug; the offer had four locations. `employmentTypes` contained five items: the original PLN and conversions to other currencies. An item included the numbers `from`, `to`, `fromPerUnit`, `toPerUnit`, the strings `currency`, `currencySource`, `type`, `unit` and the boolean `gross`; do not treat conversions as separate contracts. `requiredSkills` and `niceToHaveSkills` are arrays of objects with `skillId`, `name`, a numeric `level` and `group`; the second was empty. `languages` contained `code` and `level`. `applyUrl`, `companyProfileSlug` and `hybridWorkSchedule` were null. These are the observed types and values of one offer, not a declaration of required fields or permitted values in all records.

The detail was an object without a `data` wrapper, with `id` equal to the `guid` of this sample, `slug`, `canonicalSlug`, `url`, the title and the company. `body` was HTML text; there were also `companyUrl`, `companySize`, `countryCode`, `locationId`, `isActive`, `expiredAt`, locations, contracts, technologies and languages; `informationClause` and `futureConsent` contained texts related to applying. `applyUrl`, `hybridWorkSchedule` and several company profile fields were null. `isActive: true` and the `expiredAt` date describe this particular observation; the behaviour after closing and the meaning of a 404 were not established. The UUID identifier is promising, but its durability and relation to different locations or republications were not proven.

The current [robots.txt](https://justjoin.it/robots.txt), read in the browser, has the entry `Disallow: /api/` for `User-agent: *` and refers, among others, to the [map of active ads](https://justjoin.it/sitemaps/active-jobs.xml). This is an instruction for robots, not a licence or proof of permission; the map also requires an assessment of terms and scope. No request limit, `Retry-After`, retry policy or availability was established. No official RSS was found.

### Working adapter protocol

After access terms are agreed: list `GET /api/candidate-api/offers` with `from=0` and an agreed `itemsCount`; for each page, validate the `data` and `meta` object, save the results, then use `meta.next.cursor` as the next `from`, without assuming a fixed step. A detail request `GET /api/candidate-api/offers/{slug}` delivers the description; handle a slug change and a `guid`/`id` mismatch as identity uncertainty. This describes observed behaviour, not a stable API or a confirmed contract.

Store at least the source `guid`/`id`, slug and URL, the observation time, the title and the publishing company; the values of dates, place, mode, experience, working time, contracts and salaries with currency, unit, gross/net and a conversion marker; required and optional skills and languages; the raw description and availability status, if the terms allow. Keep absent, null and an empty array distinct, if the source allows; without evidence do not assume that absence means no requirements. Sanitise HTML before display. The publishing company's name does not prove the identity of the employer or the client; `remote` does not prove that work from Poland is possible.

Filters must be configurable for any technologies, and also for salary, location, contract, working time, seniority and mode. The page interface presents these categories, but the equivalents and semantics of API parameters were not confirmed. In particular, the `java` category is not proof of a full list of technologies. For technologies, the variants any/all/excluded and the distinction between required and optional are needed; when the source does not provide the data or matching semantics, fetch an agreed wider scope and assess locally with an explicit unknown, without silent rejection. Narrowing the scope with a remote filter without proof of its completeness may lose offers.

End a run only after a verified cursor end condition; a cursor cycle, a page limit, invalid JSON or detail, missing permissions, a network error and an interruption mean an incomplete sync. Even a proper end does not prove completeness until the operator confirms the scope and the `totalItems` limit. Record the time and scope of each trial, keep previous observations and do not mark a disappearance in an incomplete run as expiry. The `isActive` status, `expiredAt` and the reactions to a removed detail need further confirmation; changes detected by comparison are a history from the first observation, not an archive of the source.

**Consequences for the project after obtaining permission:** store provenance, the detection and read time, raw values and, separately, the change history, in line with the agreed retention. Keep the URL and any identifier from the approved contract, without assuming the slug is durable. Ending through a limit, an error, a schema change, or an invalid or repeating cursor should mean an incomplete sync; the absence of an ad in such a run does not mean expiry. Our own comparison of consecutive observations can build a history from the moment it starts, but it does not reconstruct earlier versions or replace the source `updated_at`. Keep the description, salary data and geographic restrictions as unknowns when there is no evidence of their value.

## Next step: agree access

The point of contact may be **support@justjoin.it**, given by the operator in the [panel help](https://knowledge.justjoin.it/pl/articles/4662018), or **sales@justjoin.it**, given in the [English help](https://knowledge.justjoin.it/en/articles/4662018) for commercial matters. A separate address for an API partnerships team was not confirmed; ask to be forwarded to the right team. No message was sent.

In the enquiry, describe a private single-user application, daily sync and manual refresh, potential use of description excerpts in an external AI, and keeping history after expiry. Ask for:

1. Official read access, documentation or a partner channel/RSS, the authorisation method and cost, and written confirmation of the permitted use.
2. The scope of offers and fields, filters for any technologies, seniority, location, remote, contract and salary range, handling of offers without data, the full description and availability from Poland.
3. A stable identifier, pagination and completeness, publication/change/expiry dates, withdrawals, republications, and the possibility of incremental sync and history.
4. Limits, frequency and retry rules, attribution/linking requirements, the period and scope of storage, terms for sending excerpts to AI, and records after an ad disappears.

Until a reply is received, the source remains a candidate for later integration; for searching, the service's interface can be used in line with the current terms.
