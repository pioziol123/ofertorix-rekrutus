# Bulldogjob — access to source ads

Date verified: **2026-11-03**. This study supplements the [source comparison](../zrodla-ofert.md); PHP and Senior are only filter examples, and the scope of technologies and levels remains configurable. The operator's public pages, the terms of service, and search results for official API and RSS documentation were checked. Single diagnostic reads were made in the browser, without running an import; limits were not examined and restrictions were not bypassed. The search engine may show cached copies.

## Conclusion

**A potentially useful source of IT offers for various technologies and levels, but access for automated sync must be agreed with the operator.** No confirmed official API documentation for reading offers and no official RSS channel of offers were found. This is the result of a search, not proof that such services do not exist. The [offer for companies](https://bulldogjob.pl/for-employers/pricing) mentions ATS integration in the context of publishing offers; it does not confirm the right to read the whole database. The browser interface or a possible undocumented endpoint is not a public API contract.

[Terms §16 sec. 3](https://bulldogjob.pl/terms/general#page=12) stipulate that the employer, the user and third parties are not entitled to copy, modify, reproduce, distribute or download the service's content in whole or in part. Before building an import and storing content, explicit terms or the operator's consent for the specific use must be obtained. This is a practical conclusion from the terms, not a legal ruling on all exceptions.

## What the browser confirms

[The offer list](https://bulldogjob.pl/companies/jobs) shows filters for location and radius, position, technology, experience level (including Senior), type of engagement (full-time, part-time, freelance), and a PLN salary range with an option to show only offers with a salary range. There are separate [PHP](https://bulldogjob.pl/companies/jobs/s/skills%2CPHP) and [Senior](https://bulldogjob.pl/companies/jobs/s/experienceLevel%2Csenior) pages; one PHP and Senior combination was checked on a small sample, without proof of completeness. The view and its address do not document a machine contract, the semantics of all filters or a guarantee that a PHP search returns all relevant roles.

The example [Devire ad: Senior PHP Developer](https://bulldogjob.pl/companies/jobs/258259-senior-php-developer-devire) gives PHP/Symfony or Python, experience, English B2, requirements and, separately, nice-to-have items, a rate of 150–180 PLN net + VAT per hour B2B, full-time and "Zdalny Polska" (Remote Poland). The company presents itself as a recruitment firm, which does not establish the identity of the employer or the client. The page also shows a date and a number of days of validity; without a field description, do not assume that a lone date is the publication or expiry date. This is a single example, not a representative sample of field completeness.

[The Telemedi ad](https://bulldogjob.pl/companies/jobs/260419-senior-fullstack-developer-2-0-php-react-cursor-windsurf-warszawa-telemedi) gives a salary range of 25–32 thousand PLN net B2B in the text, but only "Od 25 000 PLN" (From 25 000 PLN) in the summary; it also shows required and nice-to-have technologies. Data from different fragments may differ in detail; it is worth keeping the context and the unknowns. Remote labels alone do not always settle whether work from Poland is possible, the number of office days or a required permit.

## Technical access model — findings and limitations

**Trial of 2026-11-03:** the public list, the second page, the PHP + Senior combination and one detail were opened without logging in, in the browser; the `script#__NEXT_DATA__` element was read from the DOM. This is data actually returned to the browser, not a declaration by an external product. The browser rendered the pages but did not expose HTTP statuses here; a direct `curl` ended with a DNS resolution error (`000`), so it is not a measurement of the service's status. Views may differ over time, by language, region and configuration. They are not an official API contract.

A separate controlled `GET /companies/jobs` from the worker container via Python `requests`, without a proxy and automatic redirects, returned **HTTP 403 text/html**, 5456 bytes. The browser and the worker are separate environments; the cause of the difference is not established. The block was not bypassed.

| Element | Observation and meaning for the adapter |
| --- | --- |
| List | `GET /companies/jobs` returns a page containing the JSON `__NEXT_DATA__.props.pageProps`: `jobs` (array), `totalCount` (number), `slugState` (object). In the trial: 50 records, `totalCount: 1046`, `slugState.page: 1`, `perPage: 50`. The number changes over time. |
| List record | `id` is a **string with a number and a slug**, e.g. `257697-senior-software-engineer-linux-krakow-luxoft-dxc`; `position`, `city`, `experienceLevel`, `employmentType`, `locale` are strings; `technologyTags` an array of strings; `remote`, `showSalary`, `hiddenBrackets`, `matchingUserBrackets` booleans. `contractB2b`, `contractEmployment`, `contractOther` were bool or null; `redirectTo` and `highlight` were null in this sample. `company` contains, among others, `name` and `logo.url`; `environment.remotePossible` was null in the sample. The types are an observation, not a guarantee for all records. |
| Salary on the list | `denominatedSalaryLong` is an object with `money` (range text or null), `currency` (string or null), `hidden` (bool). In one sample `money: "22 000 - 25 000"`, `currency: "PLN"`; the text alone does not establish the period or the basis. Do not invent values for null. |
| Pagination | Clicking page 2 changed the URL to `/companies/jobs/s/page,2`. When opening this address directly: `slugState.page: 2`, `perPage: 50`, 50 records, `totalCount: 1046`. The same offer names and locations appeared in both views; without comparing full identifiers this does not prove duplicates, but a dynamic order does not guarantee a consistent snapshot. The last page, a full traversal and the stability of the numbers were not checked. |
| Filters | The single address `/companies/jobs/s/skills,PHP/experienceLevel,senior` returned 9 records and `slugState.filters` with `skills: [{value: "PHP", label: "PHP"}]` and `experienceLevel: ["senior"]`. The first record had, among others, Symfony, React and TypeScript in `technologyTags`, but not PHP; filtering on the visible list tags alone could wrongly reject it. This does not prove completeness or the semantics of arbitrary combinations. The technology is an example, not a default setting. |
| Detail | In [the Devire example](https://bulldogjob.pl/companies/jobs/258259-senior-php-developer-devire) `__NEXT_DATA__.props.pageProps.data.job` is an object; `id`, `position`, `state`, `publishedAt`, `endsAt`, `offer`, `requirements`, `employmentType`, `experienceLevel`, `mainTechnology`, `locale` are strings; `roles`, `technologyTags`, `workFrom`, `workModes`, `locations`, `benefits` arrays; `company`, `environment`, `howWeCode`, `howWeManage`, `howWeTest`, `tools` objects; `details`, `recruitmentProcess`, `redirectTo` were null. This is a sample of one record; other fields may have other values or types. `offer` and `requirements` contain the content; do not replace the whole page with them without examining all variants. |
| Dates and pay in the detail | In this sample `publishedAt: 2026-10-14T08:30:08+02:00`, `endsAt: 2026-11-13T23:59:59+01:00`, `state: published`; `b2bSalary` contains `money: "150 - 180"`, `currency: "PLN"`, `timeframe: "hour"`, `minValue: null`, `maxValue: null`, `hidden: false`. `employmentSalary` and `otherSalary` were null. The names indicate the purpose of the dates, but the update and state rules need confirmation; do not compute amounts from null without careful text parsing. |
| Addresses and application | In this sample the source URL can be built from `https://bulldogjob.pl/companies/jobs/` + the observed `id`; also keep the URL obtained from the link. `redirectTo` may be an application link according to [the career-ops documentation](https://github.com/career-ops-hq/career-ops/blob/main/docs/SUPPORTED_JOB_BOARDS.md), but it did not occur in our sample; do not equate it with the ad URL. |
| Contract and limits | No official specification of reading, authorisation, versioning, limits, SLA or schedule was found. The public view is not consent to automation. `robots.txt` could not be read; CAPTCHA and protections were not tested. |

[The description of the independent career-ops integration](https://github.com/career-ops-hq/career-ops/blob/main/docs/SUPPORTED_JOB_BOARDS.md) and [the career-ops-ui 1.265.0 release](https://newreleases.io/project/github/Fighter90/career-ops-ui/release/v1.265.0) describe the same `__NEXT_DATA__` and pagination model; their page limits are integration settings, not Bulldogjob limits. The adapter code could not be fetched independently. [Apify](https://apify.com/datawatcher/bulldogjob-scraper) describes its own actor with a separate detail fetch and local handling of some filters; this is a third party's declaration, not a contract or Bulldogjob's consent. Its [OpenAPI](https://apify.com/datawatcher/bulldogjob-scraper/api/openapi) concerns calling the Apify actor.

### Proposed adapter protocol once terms are set

1. Accept a configurable scope: no technology means a broad list; filter values and combinations are user settings. Conservatively fetch a wider scope, and assess conditions whose source semantics were not confirmed locally after the detail, keeping the unknowns. Do not equate full-time with the contract type, or `Remote` with the right to work from Poland.
2. Read the list HTML, safely parse the JSON from `__NEXT_DATA__`, check the shape of `jobs`, `totalCount`, `slugState` and explicitly go through the subsequent `/s/.../page,N`. Keep `id`, the source URL, the list fields and the observation time; deduplicate by the observed `id`. Guard against order changes and count discrepancies; a shorter page or record count alone does not prove atomic completeness. Determine the end according to a confirmed contract and mark missing pages or a limit as an incomplete run.
3. Fetch the detail for each ad in scope, check `data.job` and map the content, requirements, publishing company, technologies, locations/work mode, contract types and pay, dates and status together with the source values. Leave gaps and unknown variants as unknowns; distinguish the publisher from the employer and the client. Report schema changes, errors of single details, 429, 403, CAPTCHA or other blocks and stop in line with the terms, without bypassing protection.
4. Save the raw material within the permitted scope, the mapping version, and the first and last observation. Compare versions locally; a complete run can establish unavailability, not expiry. Repeat at an agreed pace; do not take unknown limits or frequencies as consent.

### Storage design once access is obtained

Keep separately the source URL, the observed identifier, the raw material and the mapping version, the time of the first and last observation, and the source dates with their uncertain semantics. Ad versions and changes must be built locally from consecutive valid observations; no source history, change cursor or webhook was discovered. Formatting changes must be distinguished from material content changes, and errors, truncated pages or a changed schema treated as an incomplete sync, not expiry. Refreshing an ad or republishing it may change the dates or the identifier: there is no guarantee that the URL number stays the same. The scope of storage and of passing data to AI requires separate terms for this source.

## Identification and sync

- The example offer's address contains the number `258259` and a text slug. This is an observation of the URL format, **not a confirmed guarantee of a stable identifier**, or of keeping the number after a change or republication. Ask for a durable key and republication rules.
- A single trial confirmed the `/s/page,2` segment and 50 records on two pages; completeness, atomicity and stability of pagination were not confirmed. This is a user page address, not a documented integration endpoint.
- `state` and `endsAt` were observed in the detail; no official contract was found for them, nor a contract for changed records, `updated_at`, version history, webhook or deletions. The absence of an ad in an incomplete run does not mean expiry; even a full check confirms at most unavailability, unless the source gives an expiry state.
- No guarantees of completeness, retention period, limits, cache, SLA, authorisation, cost, API fields or change policy were established. Reading [robots.txt](https://bulldogjob.pl/robots.txt) with the web tool failed; no conclusions were drawn from it. Even an available robots.txt does not replace a licence or the terms.

Current trials from 2026-11-03: [matrix and conclusions](naglowki-http.md). NFJ HTML and API return 200 after changing only the User-Agent to Chrome, while the base client still gets 403. ## Update: working curl_cffi transport

On 2026-11-03 reading Bulldogjob **.pl** and theprotocol from the container was confirmed via curl_cffi with a Chrome/Safari profile and HTTP/2, without the owner's cookies. The list, the second and last page, a filter and a detail returned 200 and application data. Plain requests, plain curl HTTP/2 and the Chrome profile forced to HTTP/1.1 still received a challenge. The earlier technical block was resolved in a diagnostic sample. [Results, limitations and reproducers](dostep-http-rozwiazanie.md). Connectors and full import have not been implemented yet.
