# JobSpy: other portals, limits and new sources in forks

Analysis date: 2026-11-03. Static analysis of public code and the GitHub API; no traffic to job portals, and no installing or running of fork code. Conclusions about the number of Senior PHP offers available from Poland remain a hypothesis to check later. `remote` does not prove that employment from Poland is possible.

## Recommendation

Do not choose a whole fork as a new dependency just because it declares "fix 429". The most useful are small, selected changes: shared control of all requests and separate adapters for sources with a public API/feed. For this project, the order of sources that follows from the reviewed code: SOLID.Jobs, RemoteOK, then Freehire as an experiment; WTTJ and Wellfound have more limitations. This is a ranking of technical and geographic usefulness, not a measured ranking of the number of PHP offers.

## Limits and blocks: what was found outside Indeed

Reference point: upstream [`68b88d6909a2342ad75fbb945c4204a3a7ed6665`](https://github.com/speedyapply/JobSpy/commit/68b88d6909a2342ad75fbb945c4204a3a7ed6665), dated by GitHub to 2026-10-27. The current transport has a 15 s timeout, proxy rotation and Chrome impersonation; it has no general limiter and no automatic retries. [`check_status`](https://github.com/speedyapply/JobSpy/blob/68b88d6909a2342ad75fbb945c4204a3a7ed6665/jobspy/util.py#L37-L108) describes 403/429 together with a hint about proxies, which does not identify the cause of the block.

## Consequences for integration

Each adapter must distinguish a valid empty result from an incomplete source sync. A 429/403 error, invalid JSON or interrupted pagination must not mean that source ads have expired. Store the raw geographic restrictions; the `is_remote` field is not enough to assess whether work is available from Poland.

In line with the user's consent for LinkedIn/Indeed, the limit is at most one HTTP request per second, covering search, details, redirects and retries. A pause between `scrape_jobs` calls or between pages does not guarantee this condition. Recommendation: one point for sending requests with an interval of at least 1 s without accumulating tokens, shared by all parallel runs; `Retry-After` as an additional minimum block, and 403/CAPTCHA as a stop instead of automatic identity rotation. This is an architectural recommendation, not an existing feature of the examined new adapters.

## Scope and limitations of the evidence

The GitHub API was read for open PRs and for the first 20 forks sorted by stars and the 20 newest. This is a limited review, not an audit of all forks. The popularity of the forks is very low (the leader of the sample: 4 stars), so the star count is not meaningful evidence of quality here. Data indexed by a search engine is sometimes older than the API response: for example, the PR369 page showed the old SHA `61e6937`, while the API returned `02b6437…`. In the API reads above, no dates later than the study date were found; any future dates from other snapshots must be treated as a discrepancy, not as confirmation of the state on 2026-11-03.
