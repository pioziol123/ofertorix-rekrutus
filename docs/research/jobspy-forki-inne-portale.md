# JobSpy: inne portale, limity i nowe źródła w forkach

Data analizy: 2026-11-03. Analiza statyczna publicznego kodu i GitHub API; bez ruchu do portali z ofertami, instalowania ani uruchamiania kodu forków. Wnioski o liczbie ofert Senior PHP dostępnych z Polski pozostają hipotezą do późniejszego sprawdzenia. `remote` nie dowodzi możliwości zatrudnienia z Polski.

## Rekomendacja

Nie wybierać całego forka jako nowej zależności tylko dlatego, że deklaruje „fix 429”. Najbardziej przydatne są małe, wybrane zmiany: wspólna kontrola wszystkich żądań oraz osobne adaptery źródeł z publicznym API/feedem. Dla tego projektu kolejność źródeł wynikająca z przejrzanego kodu: SOLID.Jobs, RemoteOK, następnie eksperymentalnie Freehire; WTTJ i Wellfound mają więcej ograniczeń. To ranking przydatności technicznej i geograficznej, nie zmierzony ranking liczby ofert PHP.

## Konsekwencje dla integracji

Każdy adapter musi odróżnić pusty poprawny wynik od niepełnej synchronizacji źródła. Błąd 429/403, niepoprawny JSON lub przerwana paginacja nie mogą oznaczać wygaśnięcia ogłoszeń źródłowych. Przechować surowe ograniczenia geograficzne; pole `is_remote` jest niewystarczające do oceny dostępności pracy z Polski.

Zgodnie ze zgodą użytkownika dla LinkedIn/Indeed granica wynosi najwyżej jedno żądanie HTTP na sekundę, obejmując wyszukiwanie, szczegóły, redirecty i ponowienia. Pauza między wywołaniami `scrape_jobs` ani między stronami nie gwarantuje tego warunku. Zalecenie: jeden punkt wysyłania żądań z odstępem co najmniej 1 s bez kumulowania tokenów, wspólny dla wszystkich równoległych przebiegów; `Retry-After` jako dodatkowa minimalna blokada, a 403/CAPTCHA jako przerwanie zamiast automatycznej rotacji tożsamości. To zalecenie architektoniczne, nie istniejąca funkcja przebadanych nowych adapterów.

## Zakres i ograniczenia dowodów

GitHub API odczytano dla otwartych PR-ów i pierwszych 20 forków sortowanych po gwiazdkach oraz 20 najnowszych. Jest to ograniczony przegląd, nie audyt wszystkich forków. Popularność forków jest bardzo niska (lider próby: 4 gwiazdki), więc liczba gwiazdek nie stanowi tu sensownego dowodu jakości. Dane indeksowane przez wyszukiwarkę bywają starsze niż odpowiedź API: przykładowo strona PR369 pokazywała stary SHA `61e6937`, API zwróciło `02b6437…`. W powyższych odczytach API nie stwierdzono dat późniejszych niż data badania; ewentualne przyszłe daty z innych snapshotów trzeba traktować jako rozbieżność, nie potwierdzenie stanu na 2026-11-03.
