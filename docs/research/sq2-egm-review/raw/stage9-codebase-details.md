# Stage 9 — Codebase details (egm-codebase-details), Implementation Readiness

Scope: docs/specs/sq2-zlecenia-ai/solution-design.md (SD), docs/research/sq2-egm-review/tickets-export.md (tickets). Code checked: local `main` (dd24a87) and `origin/main` (45c1769, 11 commits ahead of local main).

## 🟡 Major

**M1. The "code observed" baseline is stale: the queue and worker libraries already exist.** SD L9 says the queue and worker libraries come "from the background work design, not from code". On `origin/main` the work of `oferty-pracy-2ba.1`, `2ba.4` and `2ba.5` is merged: `lib/queues/*` (`defineJob`, `sendJob`, `createQueue`), `lib/workers/*` (`HandlerRegistry.register(definition, handler, failureHandler)`), `plugins/index.ts`, `queues.json`, `WORKER_POOL_SIZE` in compose.yaml, queue migrations 0022/0023. The local `main` checkout is 11 commits behind and has none of them. Why it matters: the implementer should build on the real APIs. The SD should cite them and re-baseline on `origin/main`. They match the design (the handler and the failure handler get only the job's data, and a second registration throws), so this is a baseline problem, not a contradiction.

**M2. Cause list in the "closed lists" contract (SD L85) misses `interrupted` and `adapter_unavailable` as current members.** The code (modules/ai/domain/execution-state.ts) has 13 causes. The SD names 11 and then says that two "are not written any more". That wording is correct, but the database check on the new operation table must say whether those two are excluded. The contract is silent, so the implementer has to decide (zero-decision rule).

**M3. The delivery queue has no failure handler and no defined final failure (SD L46, L250–256).** On the worker library, a final failure (pg-boss defaults: 3 attempts, 15 min, B1-D02) goes to `<queue>.failed` and calls the failure handler, if one is registered. The SD defines failure handlers only for the executors' queues (L218). Gap: after a delivery fails finally, a succeeded operation's assignment stays `in_progress` and undelivered. Then the time-limit pass (L258) only skips assignments with a *running* operation. It would fail this one with `time_limit` and drop the result. That contradicts the "no result can be lost" claim of ZA-D06. The design must define a failure handler for the delivery queue, or a rule for this case.

**M4. Coexistence with B6 in the periodic process and the budget is not specified against the code (ZA-D07, SD L80, L192).** Today `reserve()` (modules/ai/infrastructure/persistence/budget.ts) computes room from `ai_attempts` only (`settled` → actual_pln, otherwise reserved_pln) and hard-codes `defaultLimit='100.000000'`. The SD says the room "also" subtracts the old attempts while both ways exist. It does not say that the old `reserve()` must also subtract the new operations' charge. Without that, the old way overspends. The SD also does not say that the default limit moves from the code constant to the new one-row table, for both ways. The order of the new steps next to B6's five periodic steps is also left open.

**M5. T10 carry-over of charge does not match the current attempt states (SD L315).** `ai_attempts.state` values in the code are `queued`/`waiting_budget`/`running`/`settled`/`unknown`, and migrations 0017–0019 set never-started ones to `settled` with `actual_pln=0`. The rule "the reserved amount of those of unknown cost and of those whose work had started and not ended; nothing for those that never started" needs the exact state-to-amount mapping. In particular, today a `queued` attempt already holds a reservation that counts against the month. The SD's rule changes what counts as charged at the migration, and it does not say so.

**M6. "Columns that hold an execution identifier today are replaced" (SD L285) is not enumerated.** The real columns are `profile_imports.current_execution_id` and `current_publication_token` (migration 0013), `matching_requests.execution_id` (0018) and `company_research.execution_id` (0019), with foreign keys to `ai_executions`. T10 L316 renames the old tables to an archive prefix. The foreign keys from the module tables, and the archive rename of `ai_executions` itself, are not addressed. That is a schema decision left to the implementer. T10 L316 also does not name the "columns of the former Profile path" (presumably `result_status`, `error_code`, `disposition`, `publication_allowed`, `runtime_state`).

**M7. File boundary and steps are left to the implementer (standard: Target Scope).** SD L5 explicitly "leaves names, files and paths to the implementer". No ticket lists Create, Modify or Delete paths. Under the Implementation Readiness Standard this fails the file-boundary requirement. Reported once, as the persona requires.
